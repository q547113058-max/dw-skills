# 执行清单

本清单只记录 DW 相对 Superpowers 的增量工作。组合模式下不要重复勾选 Superpowers 已负责的通用阶段。

## 启动

- [ ] 检查 Git 状态、分支、最近提交和用户已有改动。
- [ ] 读取相关项目文档、最近日志和唯一任务清单。
- [ ] 记录 `Mode: combined` 或 `Mode: standalone`。
- [ ] 组合模式下识别当前 Superpowers 阶段和已有产物，不重新生成。
- [ ] 只加载本任务触发的 DW 文档和 Skills。

## 增量规则

- [ ] UI 任务加载设计标准，并记录产品上下文、风格方向、token 和禁用项。
- [ ] UI 任务检查已有设计系统、组件和品牌资产，避免复制受保护资产。
- [ ] 先使用 `rg`、相关文件和现有测试；只有确有价值时才升级到 codegraph、Graphify 或 agentmemory。
- [ ] 调用登记 Skill 时遵守更新策略；不要为了形式检查未调用的 Skill。
- [ ] 写代码前走精简实现阶梯，搜索可复用实现和共享入口。
- [ ] 安全、技术栈、AI eval 或领域规则只在触发条件成立时启用。
- [ ] 网络代理只用于确认存在的联网故障，并限制在当前命令。

## 实现

- [ ] 改动只覆盖当前计划步骤，保留用户已有改动。
- [ ] Bugfix 修根因；不新增未请求的抽象、依赖或未来扩展。
- [ ] 决策影响产品、数据模型、UI 结构或安全边界时同步文档。
- [ ] 组合模式下使用 Superpowers 的唯一计划和任务状态，不维护平行 TODO。

## 验证

- [ ] 接受并引用 Superpowers 已有的 RED/GREEN、review 和 verification 证据。
- [ ] 运行尚未覆盖且与变更相关的项目真实检查。
- [ ] UI 工作补充桌面/移动、响应式、可访问性和视觉 QA。
- [ ] 敏感变更补充安全审查；技术栈明确时补充专项检查。
- [ ] 做一次有证据的精简审查，删除重复实现和不必要抽象。
- [ ] 记录无法运行的检查和剩余风险，不用重复审查制造虚假确定性。

## 交付

- [ ] 实质性任务更新开发日志，包含模式、当前阶段、变更、验证和恢复入口。
- [ ] 汇总 Superpowers 证据与 DW 增量检查，不复制完整报告。
- [ ] 根据用户授权提交、推送或创建 PR；不擅自合并、force-push 或改仓库设置。
- [ ] 最终说明提交/推送状态、验证结果、未解决问题和下一步。

## 反重复

- [ ] brainstorming 已确认设计后，不再要求完整需求模板。
- [ ] writing-plans 已生成计划后，不再创建 DW 阶段计划。
- [ ] test-driven-development 已执行后，不再建立第二套 TDD 周期。
- [ ] review/verification 已覆盖通用质量后，只运行项目特有门禁。
- [ ] finishing-a-development-branch 已给出分支选择后，不创建冲突的 Git 流程。
