# 质量门禁和审查

质量门禁只补充项目真实风险。复用仓库 CI、当前模型、Superpowers 或其他已启用工具提供的最新证据，不创建第二套测试、审查或任务状态。

## 分级验证

- `quick`：最接近改动的测试、lint/build 片段或人工检查，加 diff 审查。
- `standard`：项目已有且与改动相关的 formatter、lint、type check、tests 或 build。普通 Bugfix 在存在可靠测试面时补回归测试。
- `high-risk`：在 `standard` 基础上，只增加与具体风险相关的权限、失败、兼容、恢复和集成/E2E 验证。

不要求运行所有可用命令。跳过关键检查时说明原因；工具缺失本身不阻塞交付，但不能把未运行报告为通过。

## 门禁强度

### 轻量检查

适用于普通输入处理、CRUD、可逆 schema、非敏感 API、本地文件、内部架构和 CI 配置：

- 检查主要成功路径和最可能失败路径。
- 检查改动范围、兼容性和错误传播。
- 使用现有测试面，不强制独立审查、E2E 或回滚演练。

### 完整审查

仅适用于认证授权、secrets、支付、客户/敏感数据、破坏性 migration、生产发布、公开契约破坏、特权或不可逆操作：

- 审查权限、数据暴露、失败后果和恢复能力。
- 验证正常、失败和关键边界场景。
- 在通用审查无法覆盖专项风险时增加独立安全、数据或部署审查。

CRITICAL/HIGH 安全问题在交付前修复，除非用户明确接受且不违反硬边界。

## 精简审查

代码编辑后检查：

- 是否重复已有 helper、标准库、平台或依赖能力。
- 是否新增未请求的接口、包装层、配置层或脚手架。
- Bugfix 是否位于根因和共享入口。
- 删除样板后是否仍保持行为和可测试性。

只报告有证据的问题；没有发现时一句说明即可。

## 交付摘要

`quick` 只列实际检查和剩余风险。`standard` 简述相关验证；`high-risk`、发布或交接才使用完整风险摘要。只有最新证据支持时才能宣称通过或可交付。
