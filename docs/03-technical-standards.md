# DW 风险与技术边界

仓库规则、用户要求和当前模型的工程能力优先。本文只在安全、数据、部署或外部操作门禁命中时读取相关部分，不因出现某项技术就自动升级整个任务。

## 按影响分级

- `quick`：影响局部、无敏感边界、容易验证和回滚。
- `standard`：普通行为、内部架构、数据库 CRUD、可逆 schema addition、非敏感外部 API、本地文件和 CI 配置变更。
- `high-risk`：认证或授权、secrets、支付、客户/敏感数据、破坏性 migration、生产发布、公开契约破坏、特权操作、不可逆外部 mutation 或恢复成本显著。

文件数量和使用数据库、文件系统或 API 本身不是升级理由。按数据敏感度、权限、影响范围、可逆性和失败后果判断。

## 轻量边界检查

普通 `standard` 任务只检查实际命中的边界：

- 输入/API：验证必要字段、错误响应、超时和失败传播。
- 数据：验证读写范围、事务或幂等需要、兼容性和完整性。
- 文件：验证路径范围、编码、覆盖行为和失败处理。
- CI/配置：验证语法、目标环境和默认值，不要求生产回滚演练。
- 外部只读：确认来源和结果真实性，不需要 mutation 授权。

## 完整高风险检查

只有命中 `high-risk` 条件时，才增加相关项：

- 权限绕过、越权和最小权限。
- secrets、隐私、日志和公开 bundle 暴露。
- 破坏性写入、兼容窗口、备份和恢复。
- 失败路径、部分成功、重试、幂等和审计。
- 生产发布、回滚条件和可行的集成/E2E 验证。

不要求无关专项审查，也不为不存在的脚本或环境编造证据。

## 项目决策

只有难以撤销、缺少背景会令人困惑且存在真实权衡的决定才创建 ADR。依赖、数据模型、构建或部署选择优先遵循项目已有决策格式。

GitHub mutation 按 `docs/08-github-update-standard.md`；确定性验证和专项审查按 `docs/09-quality-gates-and-review-loop.md`。
