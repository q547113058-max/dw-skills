# 执行追踪、质量分级和反馈归因

每个任务结束时，以及收到反馈时，使用本标准。

## 执行追踪

记录：

- 任务
- 阶段
- 变更文件
- 运行的命令或检查
- 结果
- 阻塞项
- 下一步

建议格式：

```text
执行轨迹：
- Task:
- Phase:
- Files:
- Checks:
- Result:
- Blockers:
- Next:
```

## 质量分级

交付前给出等级：

- `A`：需求满足，相关检查通过，没有已知阻塞问题。
- `B`：需求基本满足，有轻微已知问题或跳过的低风险检查已记录。
- `C`：部分完成，但存在明显限制、未验证行为或需要后续修复。
- `Blocked`：无法安全交付，需要用户输入或外部状态变化。

质量等级必须与证据一致，不能因为接近结束就给高分。

## 异常检测

检查以下异常：

- 同一命令或检查重复失败
- 跳过关键验证
- 需求仍不清楚
- 出现意外 diff
- 测试回归
- 工具超时或网络失败
- 生成文件缺失
- UI 重叠、裁切或不可读
- 安全敏感路径未审查

异常要记录到当天日志。

## 反馈归因

反馈出现时，归因到一个主要来源：

- 需求缺口
- 规划缺口
- 实现 Bug
- 设计问题
- 验证缺口
- 工具问题
- Agent 规则缺口

归因格式：

```text
反馈归因：
- Feedback:
- Likely source:
- Evidence:
- Fix:
- Rule update needed:
```

## 规则更新

如果反馈暴露重复 Agent 规则缺口：

1. 在 `AGENTS.md` 添加简洁规则。
2. 规则写清：
   - 触发条件
   - 必须行为
   - 禁止行为
3. 在当天日志记录新增规则和原因。

不要添加模糊提醒。规则必须能被未来任务直接执行。
