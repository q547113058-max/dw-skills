# DW Skills

DW adds project governance. It does not restate generic model or Superpowers development behavior.

## Start

1. Read `AGENTS.md` and select `quick`, `standard`, or `high-risk`.
2. Select `combined` when Superpowers is available; otherwise use `standalone`.
3. Load only references triggered by the task.

## Ownership

- Combined: Superpowers owns the generic lifecycle; reuse its artifacts.
- Standalone: the active model follows user and repository rules using real tool evidence.
- DW owns project-specific UI context, second-brain recovery, tool-cost routing, conditional gates, skill governance, and delivery records.
- External state such as GitHub, VPN, graphs, and persistent memory must come from tools, not model inference.

## Boundaries

- Do not duplicate plans, TDD cycles, reviews, verification, or task state.
- Do not enable second-brain routing outside `CODEX_HOME=D:\Codex\home` before cloud migration is verified.
- Do not perform GitHub mutations or install external runtimes without authorization.
